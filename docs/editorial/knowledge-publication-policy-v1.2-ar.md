# سياسة المعرفة والنشر والتصحيح — SATAC
**الإصدار 1.2 | 27 نوفمبر 2026 | توجيه مالك المشروع**

## 1. المبدأ
المعرفة المتاحة قابلة للنشر والتحسين المستمر. اكتمال التوثيق والمراجعة ليس شرطًا عامًا للنشر. غياب المصدر لا يعني الخطأ؛ ووجوده لا يضمن الصحة. لا يُختلق مصدر أو معلومة لسد فجوة.

## 2. التصحيح المباشر
- إذا ثبت الخطأ وعُرفت القيمة الصحيحة، تُصحح مباشرة بطريقة حتمية أو بناءً على معلومة موثوقة متاحة، دون انتظار مراجعة إضافية لمجرد الإجراء.
- يسجل النظام داخليًا القيمة السابقة والجديدة، سبب التصحيح وأساسه، الأداة أو الفاعل، وقت التنفيذ ومعرف النسخة. تُنشأ نسخة جديدة عند تغيير معلومة منشورة؛ تبقى الإصدارات السابقة قابلة للتتبع وفق سياسة السحب.
- إذا اكتُشف الخطأ ولم تُعرف القيمة الصحيحة، تُنشأ مهمة بحث داخلية ولا يُعرض الحقل المعروف خطؤه. لا تُعكس بداية الفترة ونهايتها تلقائيًا إلا إذا ثبت أنهما متبادلتان.
- الخلاف العلمي وعدم اليقين الحقيقي ليسا خطأً إداريًا؛ تُحفظ الروايات وتُمثل دقة الزمن والمكان بأمانة.

## 3. استقلال النشر عن التوثيق والمراجعة
- يجوز نشر معلومة سليمة بنيويًا لا يُعرف خطؤها ولو لم يُرفق بها مصدر أو كانت مراجعتها غير مكتملة. لا يشترط وجود صف Evidence أو قرار Review لإدراجها في إصدار عام.
- غياب المصدر أو محدد موضعه أو الحاجة إلى مراجعة يُنشئ مهمة داخلية قابلة للتتبع وتُحدّث عند استكمالها؛ لا يمنع النشر لهذا السبب وحده.
- لا تُنشر البيانات الاصطناعية، ولا القيم المعروفة خطؤها أو الفاسدة بنيويًا، ولا المواد المحجوبة وفق ضوابط السلامة والخصوصية والوصول التي يحددها المالك. مسألة حقوق التوزيع والترخيص مسؤولية المالك؛ يطبق الفريق الفني إعدادات الوصول التي يعتمدها.
- يُبقي الوكلاء مخرجاتهم في staging؛ خدمة النشر المخولة تطبق قواعد السلامة وتبني إصدارًا ثابتًا، دون اشتراط مراجعة بشرية لكل ادعاء أو السماح للوكيل بالكتابة المباشرة إلى النشر.

## 4. الفصل بين الحالات
تُعتمد حقول مستقلة (القيم التالية عقد هندسي مقترح):
- publication_status: draft, published, withheld, withdrawn.
- verification_status: unreviewed, review_required, verified, disputed, known_incorrect.
- source_status: missing, incomplete, available.
- correction_status: none, pending, corrected.
- epistemic_status: well_supported, plausible, disputed, uncertain, unsupported؛ لا يُستنتج من غياب المصدر وحده.

الحقول الإدارية مستقلة عن عضوية الإصدار. السجل المنشور قد يكون review_required وmissing. وصف unsupported لا يعني تلقائيًا known_incorrect.

## 5. الواجهة العامة
تعرض الأطلس والموسوعة والعلاقات والمراجع الموجودة عند توفرها، دون شارات نقص المصدر أو المراجعة، ودون كشف حقول الحالات الإدارية أو طوابير المهام أو سجلات التصحيح في API العام أو البحث أو التصدير. لا توحي الواجهة بأن كل المعلومات خضعت للتحقق. تبقى التقديرات العلمية والتعارضات التاريخية الحقيقية معلومة موضوعية ظاهرة للمستخدم.

## 6. معايير القبول الفنية
1. نشر سجل بلا مصدر وبلا مراجعة مكتملة، مع إنشاء مهمة توثيق/مراجعة داخلية.
2. تصحيح خطأ معلوم بصورة آلية مع حفظ سجل التغيير وإعادة إنتاج الإصدار؛ عدم تخمين تصحيح مجهول.
3. عدم عرض قيمة ثبت خطؤها أو سجل اصطناعي؛ بقاء بقية البيانات السليمة قابلة للنشر.
4. عدم تسرب حالات الإدارة ومهامها إلى أي مخرج عام؛ ظهور عدم اليقين العلمي الفعلي والمراجع المتاحة.
5. ثبات الإصدارات وسلامة المراجع الموجودة وإمكان التراجع وفق ضوابط السحب.

هذه سياسة معتمدة بتوجيه المالك؛ تنفيذها واختبارها الهندسي جزء من P0/P1، ولا تعني إغلاق أي مرحلة أو اعتمادًا علميًا لمحتوى قائم.
