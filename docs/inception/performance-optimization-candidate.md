## Changes
The two explore requests dominate measured latency. Source inspection shows five separate reads of the shared security-barrier projection in its contextual UNION. Candidate consolidates them into one materialized released-content scan with the same predicate eligibility, exact field extraction and UUID conversion for directory identity; retains public_read.release_claims as the sole source, including withdrawals and selective masking. Original normalization, ranking, caps and cursor unchanged. Reader additionally sets JIT off locally in each read transaction, hypothesis that LLVM startup cost is disproportionate for bounded interactive queries; no global DB setting. No claim that JIT is proven the dominant cause yet. No private/staging access, no cache, no new index, no weakening of revocation, no new data. Effect of the two changes is measured together; individual attribution requires separate profiling.
CI checks out exact prior API commit into separate directory after browser suite. On same disposable DB/runner and same workload, measure old then new server (same locked dependencies), verify per-request normalized JSON SHA-256 and compare both reports. Each workload's parameters, release, counts, next page presence and canonical response digest must match. Comparison script reports p95 reductions and A13 status, rejects changed responses; no latency threshold gate beyond recording target yet. Added three comparator unit tests. Existing SQL/API/browser and access regression retained. CI timeout raised to 20 minutes for paired measurement. No claimed improvement until paired report completes. Ordered old/new measurements may retain cache effects; sequential workload only. Future EXPLAIN profiling, larger complex polygons and concurrent read load, network/browser GPU/device benchmarks and security/accessibility remain pending. No production merge or deployment.
