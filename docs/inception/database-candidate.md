# Persistent knowledge core — database candidate 0.1

P0/P1 technical prototype under review, not closure or production deployment. Implements owner policy v1.2 in PostgreSQL 16/PostGIS 3.4. Run db/migrations/0001_knowledge.sql once as a dedicated database owner on a fresh isolated DB, then db/tests/knowledge.sql using psql -v ON_ERROR_STOP=1. The test transaction rolls back all invented fixtures. Migration creates database roles; use a disposable cluster for tests. No real legacy data imported.

Relational claims, optional evidence, durable follow-up tasks, bounded/open/unknown astronomical years (integer range +/-10^30; no historical floor in business model), WGS84 geometry with validity and coordinate checks, GiST index, public JSON snapshots, immutable release hashes, withdrawal overlay and audited successor correction. Release and correction operations are serialized with a transaction advisory lock. Reader role can read public views only; publisher role can execute release/correction functions, curator role can flag known incorrect values and read task/audit records. Roles are NOLOGIN; authentication, stage ingestion grants and service identities must be designed in P1. Database owner is trusted; this is not a security audit.

Scope: relation claims only, not typed literals or general ontology; staged successor carries the explicitly corrected time/geometry/evidence values as appropriate. No guessing; caller must supply known correction basis. Old snapshots and hashes survive withdrawal; public historical read excludes withdrawn versions. Hash uses PostgreSQL 16 JSONB textual serialization, not cross-version canonical JSON. Restricted references/geometries excluded at release creation; dynamic asset-level revocation policy still pending. Review records are durable; full task assignment/review resolution workflow, source metadata, general revisions, temporal normalization, antimeridian query, spatial API, migrations framework, concurrency stress tests, real-data migration and P1 acceptance remain open. Source and publication states are derived from evidence/membership rather than duplicating flags in this candidate. Tests use invented values in an isolated rollback transaction; the synthetic flag tests rejection independently.
