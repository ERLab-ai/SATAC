# P0 — executable publication reference

Owner policy v1.2; not a P1 production implementation. Run python -m unittest discover -s tests -v.

The in-memory reference covers entity-to-entity claims from the predicate registry only. It checks existing entities and optional source references; missing sources and review create internal follow-up reasons. Only explicitly selected eligible versions appear in release-scoped public projections. Scientific notes and existing bibliographic references are allowed; administrative fields, task reasons and correction logs are not. Known wrong values are suppressed in all public reads, including historical release reads; immutable stored manifests remain unchanged. The authorized service accepts a supplied known correction, records before/after, basis, actor and timestamp, creates a successor and replaces an active published version in a new release. It does not infer an unknown correction or authenticate whether the supplied basis is scientifically sound. Tests use isolated invented entities and source titles only; no real records migrate.

Design decisions: reference role strings simulate trust, not authentication. Release hashes cover sorted public projections before suppression; suppression is an explicit read-time overlay, not a rewritten historical hash. Tasks are derived from current versions plus flagged errors; no durable queue, assignment or resolution workflow yet. The correction method covers changed relation values, not temporal or geometry correction. No typed literals, source evidence stances, SQL transactions, persistent withdrawal audit, HTTP/API, search/export, concurrency, production authentication or PostGIS yet. Actual service transactions, authorization, access control, durable jobs, generic revision and correction, restricted source handling and integration tests remain P1 work. Do not interpret these reference tests as completed A01–A14 or P0 closure.
