# Claim review lifecycle candidate

Migration 0020 extends the existing Review table with an immutable linked event chain and compare-and-set review decisions. The curator records verified, review_required, disputed or known_incorrect with rationale and reviewer. Review completion/reopening affects only the review task; source documentation remains independent. Known error delegates to the existing withdrawal and correction-task operation; a review cannot restore an erroneous value or replace a correction. A corrected successor starts its own review history. The private view derives current verification and source states from the event chain and evidence; source status describes internal reference availability, not public access rights.

No change to released snapshot content, public search, exports or publication eligibility for unreviewed and unsourced claims. Preexisting unlinked review rows remain historical and are not automatically interpreted as managed decisions. SQL operation is restricted to the curator; no HTTP write API or authenticated individual curator UI. Reviewer attribution is supplied by the trusted operator, not verified user identity. The workflow does not automate scientific judgments, full task assignment or evidence revisions. Tests use disposable rolled-back data; CI verification pending.
